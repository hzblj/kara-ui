# @hzblj/kara-native

The `KaraUI` Expo native module — Swift in `ios/`, Kotlin in `android/` — and its raw JS bindings. Pure platform
layer: it depends on nothing else in the repo, and `@hzblj/kara-components` wraps each piece into one cross-platform
component. Autolinked into any app that installs `@hzblj/kara-ui` (a transitive dependency is enough).

## Rules

**Never name a native prop after a React Native style key** (`width`, `backgroundColor`, `shadowColor`…): Fabric
reads it as layout or style. Prefix it (`bubbleWidth`).

**Adding a view:** iOS — a folder in `ios/Views/` with the view and `+Definition.swift`, one line in
`KaraUIModule.swift`. Android — a package with an `ExpoComposeView` subclass registered by class in
`KaraUIModule.kt` (the functional registration shares one `viewType` with `@expo/ui` and drops events). JS — a folder
in `src/<platform>/` exported from its `index.ts`. Then the cross-platform component in `@hzblj/kara-components`.

**Process-wide setup happens once per process.** Every React runtime gets its own `AppContext` and runs `OnCreate`,
and two can be alive or initialising at the same time (a dev client opened by its deep link while it launches, a
reload during startup, brownfield hosts). `@expo/ui`'s modifier registries are maps with no lock on both platforms:
concurrent registration on iOS crashed in `Dictionary._Variant.setValue`. A new modifier is registered inside
`ModifierRegistration` (iOS: its `static let`; Android: its `SYNCHRONIZED` lazy), never straight from `OnCreate`, and
never unregistered in `OnDestroy` (another runtime may still draw it). A swizzle or any other global gets the same
treatment (`OpacityVisibilitySync`).

**Native changes need a native rebuild** of the app (`yarn prebuild` in the repo, then run); a new view also needs a
pod install / Gradle sync. Swift/Kotlin are not type-checked by `yarn typecheck` — build the example to verify.

**Resources by name are looked up in the app.** `UIImage(named:)` / `getIdentifier(…, "drawable", packageName)` find
the plugin's `native_icon_*` (`@hzblj/expo-native-icons`) in the app's own catalog and resources, and Gradle merges the module's `kara_glyph_*`
drawables into the same place. An iOS asset catalog shipped by this pod would not build (two `Assets.car`), which is
why app icons are generated into the app and iOS glyphs are SF Symbols.

**React Native opacity reaches UIKit through `OpacityVisibilitySync`.** Fabric writes `opacity` to `layer.opacity`,
past `alpha`, so a subtree mounted under a view at opacity 0 (Legend List containers before their first layout,
fades from 0) stayed hidden for UIKit, and Liquid Glass in it never rendered — the first row of a list opened from
cache lost its glass. The module wraps `RCTViewComponentView`'s `updateProps:oldProps:`, `invalidateLayer` and
`prepareForRecycle` and replays a change across UIKit's 0.01 threshold through `alpha`. That is why `GlassView` sets
its effect at once and never waits for its ancestors. Check the three selectors after a React Native upgrade. To
debug missing glass, compare `isInHiddenAncestor` in the effect view's `_ivarDescription` (lldb) with a working one.

**Haptics are not here.** They live in `@hzblj/expo-rich-haptics`, a package of its own in its own repo
(`hzblj/expo-rich-haptics`), which `@hzblj/kara-components` depends on. Change them there and release them there.

**The module name `KaraUI` is also the Swift module name.** An app whose Xcode target is named `KaraUI` would collide;
that is why the example is called "Kara Example".

## Zoom transition

**It lives in `@hzblj/expo-zoom-transition`** (`../expo-zoom-transition`, its own repo and pod `ExpoZoomTransition`);
this package depends on it so the pod is always there. One piece stays here: **a tapped context menu preview zooms.**
With a zoom source inside the trigger, `ContextMenuView` (`import ExpoZoomTransition`, `s.dependency` in the podspec)
renders the preview to an image, finds where UIKit shows it (a visible portal layer whose `sourceLayer` is the preview
controller's view's layer: a `_UIPortalView`'s `CAPortalLayer` up to iOS 26, AnimationKit's
`InProcessAnimatablePortalLayer` on iOS 27, where the `_UIPortalView` is hidden at zero size and shows the trigger) and
hands a copy over as a transient source (`ZoomTransitionRegistry.shared`, `ZoomTransitionTransientSource`): the photo
under a frozen snapshot of the window while JavaScript pushes, or, with `preloadedScreenId`, the whole preview with the
photo as its `focusRect` (see below). Those registry calls are the package's public API: bump it together with this
file.

## Context menu

**Once the menu shows, the trigger's press is cancelled** (`ContextMenuTouchCanceller`, from `willDisplayMenu`). The
finger still belongs to the content, so a `Pressable` inside the trigger fired its press when it lifted and the menu and
a navigation ran together. React Native's `RCTSurfaceTouchHandler` `ignore`s the touch and is then reset (`isEnabled`
toggled), which sends JS the cancel at once; the content's gesture recognizers are reset, and the canceller recognizes
itself with `cancelsTouchesInView`, so `UIControl`s get `touchesCancelled`. React Native's handler is reset only once the
touch has left it (`touch.gestureRecognizers`): reset while UIKit still gives it the touch, on iOS 27 it then gets
`touchesCancelled` for the touch it has just forgotten, and a debug build crashes on its touch registry assertion
("Inconsistency between local and UIKit touch registries").

**Files:** `ContextMenuView` (props, events, menu, targeted preview), `+Interaction` (the delegate), `ContextMenuPreview`
(renders the preview, the photo or whole-card copy), `ContextMenuPortal` (where UIKit shows the preview),
`ContextMenuPreviewZoom` (the commit into the zoom), `ContextMenuPreloadedScreen`, `ContextMenuBackdrop` +
`ContextMenuPlatterStyle` (UIKit's menu layer), `ContextMenuTouchCanceller`. They are the same as Footshop's
`platform-ui` apart from `import ExpoZoomTransition` and the doc comments: change both together.

**`onMenuOpen` / `onMenuClose(isCommitted)` come from `willDisplayMenu` / `willEndFor`**, never from
`configurationForMenuAtLocation`: UIKit asks for a configuration also on a slightly long tap that never opens the menu,
and no `willEndFor` follows it. `@hzblj/kara-components` maps them to `onOpenChange`.

**`previewTransition`** is `zoom` (the default with a zoom source), `pop` (the default without one) or `dismiss`; a zoom
that cannot happen falls back to `.dismiss`. Without the zoom, `onPreviewPress` fires once UIKit's commit animation ends
(with `.dismiss` iOS 27 reports that about 1.2 s after the preview is back on the trigger).

**With `preloadedScreenId` a tapped preview morphs into a screen that is already rendered.** The app preloads the
detail while the menu is open (React Navigation's `preload`; the route key is the react-native-screens `screenId`), and
the commit pushes it natively in the same frame (`activityState = 2` + `markChildUpdated` on the `RNSScreenStackView`,
through KVC like expo-router's `Link.Preview`, so no RNScreens import; JavaScript then moves the route into `routes` and
its prop update is a no-op). `pop` and `dismiss` push it the same way when the commit animation ends. With `zoom` the
source is a copy of the whole platter, so the screen grows out of the whole preview. UIKit's menu layer
(`_UIContextMenuContainerView`) sits above the whole app, so the commit hides the platter, fades a drawn copy of the menu
(a `snapshotView` loses the glass) and, when the zoom starts, hides the layer with `isHidden` (its own dismissal kept an
`alpha` change from showing and the dim doubled for a frame), re-creates its background under the zoom in the source
screen and on the tab bar capsule, and holds an opaque copy of the card under the zoom's crossfade for 0.15 s. On iOS 26+
that background is a dim (`_alertControllerDimmingViewColor`), not a blur. AnimationKit draws the platter's rounding, so no
layer has a `cornerRadius`: the radius is `_UIContextMenuListView._platformMetrics.previewPlatterCornerRadius` (32 pt
glass, 13 pt before), applied to the preview at its own size, so the copy uses it times the preview's on-screen scale.
Any missing private piece falls back to the frozen-snapshot zoom. React Navigation renders a preloaded screen with a
placeholder `navigation` whose `setOptions` throws, so its header must wait until the route is in `routes`.
