# example

The example app for `@hzblj/kara-ui` — where every component is proved on both platforms and both
appearances before anyone else depends on it. Private; never published.

## Map

| Path | What it is |
| --- | --- |
| `app/_layout.tsx` | Root: `Providers` + a `Stack` with the tabs, the `storybook` route (the one screen with a header), `photo/[id]` (the zoom demo's modal) and `shot/[id]` (the website's shot harness). |
| `app/(tabs)/` | Native tabs (`Tabs` from `@hzblj/kara-ui/router`): `(home)` → Home, `components` → the component catalogue (`[id]` a component's page), `design` → the design pages (`[id]` one page). Each tab is its own stack with large titles. |
| `app/storybook.tsx` | One-line re-export of `.rnstorybook`. |
| `src/providers.tsx` | Gesture root, `AppearanceProvider`, `KaraProvider` (with the picked accent theme and preference), the navigation theme, safe area. |
| `src/appearance/` | The example's only state: theme preference and accent. `accents.ts` is the reference for writing a `defineTheme` override. |
| `assets/icons/` | The example's icons — Material Symbols SVGs (Apache 2.0); `share.android.svg` is the platform-variant demo. The plugin turns them into native assets at prebuild. |
| `native-icons.d.ts` | The icon names (the global `NativeIcons`), written by the plugin whenever the config is read. Committed, so `yarn typecheck` works on a fresh clone. |
| `src/home/` | The first screen someone sees: what kara is, the live appearance/accent switch, and a small real flow (an order with a checkout sheet). |
| `src/catalog/` | The component catalogue: `catalog.ts` groups the entries from `demos/<category>.tsx`; each entry is a name, a one-line summary, what renders it (`tags`), its `Demo` and a usage snippet. |
| `src/catalog/zoom/` | `ZoomTransition`'s demo, the one that needs a route of its own: a grid of photos, the page they zoom into and the settings to try, carried as route params. The page is a root `fullScreenModal` (`app/photo/[id].tsx`), the way a gallery opens: no native header on iOS — the zoom does not reach a modal's nested header stack — so it draws its own glass close, and a drag down dismisses it. The photos are remote (picsum, fixed seeds), loaded `memory-disk` so the page has them for the zoom. |
| `src/design/` | The design pages — theme, colours, typography, spacing, shapes, shadows, styling, icons, haptics — listed in `design.ts`. |
| `src/ui/` | The example's own page parts: `Page`, `Section`, `Lead`, `CodeBlock`, `Tags`, `LinkList`. |
| `src/shots/`, `app/shot/[id].tsx` | The website's shot harness: each component alone on a stage of the screen's background (`scenes/`), sized to the 4:3 band the capture crops to. `?play=1` runs its timeline. What exists, how it is framed and what moves is `shots.json`. |
| `scripts/capture-shots.sh` | `yarn shots`: deep-links into every shot on the booted simulator and the attached emulator, in light and dark, and writes stills and seamless loops into `apps/website/public/media`. Gestures a timeline cannot play (a menu, a long press, a swipe, typing) are Maestro flows in `scripts/flows/`. |
| `.rnstorybook/` | On-device Storybook: `main.ts` globs the stories in `packages/components/src` and `packages/router/src`, `preview.tsx` wraps each in `story-frame.tsx`. `storybook.requires.ts` is generated by Metro and committed, so `yarn typecheck` works on a fresh clone. |
| `metro.config.js` | Maps every workspace package entry (`@hzblj/kara-ui`, `@hzblj/kara-theme`, …) to its `source`, blocks `contract.check.ts`, wraps in `withStorybook`. |

## Rules

**Route files hold no logic.** They re-export a screen from `src/`. Never add `.ios.tsx` /
`.android.tsx` route files — Expo Router would register them as separate routes.

**Use the library, not `@expo/ui`.** Biome blocks `@expo/ui` imports here; if the example needs
something the library lacks, that is a library change.

**A new component gets a catalogue entry and a story** — an entry in `src/catalog/demos/<category>.tsx` (its page in
the app: a summary, live examples with a caption for what to notice, a usage snippet), and a story beside the component
for Storybook's controls. Styling and tokens belong on a design page, not in the catalogue.

**Written for people, in English.** Examples use realistic content (an order, a delivery choice, settings), captions
say what to notice or where the platforms differ, and no page is a dump of props.

**Pages scroll in React Native, with a few hosts each.** A page is an `RnScrollView` of sections, each native demo in
its own `Island`. Keep a page to one component's worth of hosts: composing dozens of Compose hosts in one frame (as the
old single-scroll gallery did) stalls Android's main thread long enough for an ANR.

**Two Yarn patches serve the zoom transition** (root `resolutions`, `.yarn/patches/`): react-native-screens#4711 —
a zoom pop is reported ~0.5 s late, swallowing the next tap — and expo/expo#43338 — the dev menu's three-finger
recogniser broke the interactive dismissal in a dev client. Drop each once a release carries it.

**Native changes need a rebuild.** A change to `app.config.ts`, an SVG in `assets/icons`, the native module, or
the config plugin means `yarn prebuild` and a native run, not a Metro reload.

**A shot's timeline loops back to where it started.** A still is taken at step 0 (phase 0), and a recording is cut to
exactly one loop, so it repeats without a seam — whatever the shot shows must return to its first state by the end of
its `steps` (or `period`). Overlays open through `useOpened`, after their host has mounted.

**A loop with no period of its own fades shut.** Material's loading indicator never repeats exactly; its shot sets
`crossfade`, and the recording's end dissolves into its start. `period` and `crossfade` can differ per platform.

**`shots.py check` after every run.** Besides missing files it reports a blank still (the dev client's grey) and two
shots with one picture (a deep link the app dropped, so both show the same screen). The capture waits for the home
screen after every cold start — Android reads it from the window — because a link sent while the bundle loads is lost.

**Shots need a prepared device.** Metro running, the example installed on a booted simulator and an attached emulator,
the dev menu's welcome dismissed and its floating tools button switched off once on each, the simulator in `en_US`.

**Storybook is on unless switched off.** `EXPO_PUBLIC_STORYBOOK_ENABLED=false` makes Metro stub
`.rnstorybook` and hides the Components tab's link to it. Storybook telemetry is off unless
`STORYBOOK_DISABLE_TELEMETRY=false`.
